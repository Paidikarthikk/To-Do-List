Objective

The objective of this assignment is to identify and plan the APIs required for a To-Do List application. These APIs will be used for creating, reading, updating, and deleting tasks.

No actual API implementation is done in this assignment.

1. Add Task

Method: POST

Endpoint:

/api/tasks

Request Body:

{
  "title": "Complete Assignment",
  "description": "Finish Assignment 7",
  "completed": false
}

Logic:

The user sends the task details to the server. The server creates a unique ID for the task and stores the task. After successfully creating the task, the server sends the newly created task as a response.

2. Get All Tasks

Method: GET

Endpoint:

/api/tasks

Request Body:
No request body is required.

Logic:

The server gets all the tasks from the database and sends them to the frontend. The frontend can then display all the tasks in the To-Do List.

Example Response:

[
  {
    "id": 1,
    "title": "Complete Assignment",
    "description": "Finish Assignment 7",
    "completed": false
  }
]
3. Get a Task by ID

Method: GET

Endpoint:

/api/tasks/:id

Example:

/api/tasks/1

Logic:

The task ID is passed through the URL. The server searches for the task with that ID and returns the task details.

Example Response:

{
  "id": 1,
  "title": "Complete Assignment",
  "description": "Finish Assignment 7",
  "completed": false
}
4. Update a Task

Method: PUT

Endpoint:

/api/tasks/:id

Example:

/api/tasks/1

Request Body:

{
  "title": "Complete Assignment 7",
  "description": "Finish the API planning",
  "completed": false
}

Logic:

The server finds the task using its unique ID and updates the task information with the new details provided by the user.

5. Mark Task as Completed or Incomplete

Method: PATCH

Endpoint:

/api/tasks/:id

Example:

/api/tasks/1

Request Body:

{
  "completed": true
}

Logic:

The server finds the task using its ID and changes only its completion status. The value can be true for completed or false for incomplete.

6. Delete a Task

Method: DELETE

Endpoint:

/api/tasks/:id

Example:

/api/tasks/1

Logic:

The server finds the task using its unique ID and removes it from the database. After deleting the task, the server sends a successful response.

Unique ID Generation

Every task should have a unique identifier so that the server can easily find, update, or delete a particular task.

For example:

{
  "id": 1,
  "title": "Complete Assignment",
  "completed": false
}

The ID can be generated by the backend when a new task is created. It can be an automatically generated number or a unique ID such as a UUID.

Common HTTP Status Codes
Status Code	Meaning
200	Request successful
201	Task successfully created
400	Invalid request data
404	Task not found
500	Internal server error
API Summary
Operation	Method	Endpoint
Add Task	POST	/api/tasks
Get All Tasks	GET	/api/tasks
Get Task by ID	GET	/api/tasks/:id
Update Task	PUT	/api/tasks/:id
Mark Complete/Incomplete	PATCH	/api/tasks/:id
Delete Task	DELETE	/api/tasks/:id
Conclusion

These APIs provide the basic operations required for a To-Do List application. Using these endpoints, users can add new tasks, view tasks, update task details, change their completion status, and delete tasks. The actual implementation of these APIs can be done later using a backend such as Node.js and Express.js.
